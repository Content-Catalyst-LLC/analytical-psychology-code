# Post-Jungian Developments in Clinical Analytical Psychology

This companion scaffold supports the article **“Post-Jungian Developments in Clinical Analytical Psychology”** in the Analytical Psychology, Symbolism & the Depth Mind knowledge series.

The repository materials translate the article’s clinical argument into reproducible, synthetic-data workflows. The goal is not to diagnose people, recommend treatment, validate analytical psychology, score patients, or reduce clinical judgment to a formula. The goal is to demonstrate how symbolic depth, relational sophistication, developmental precision, trauma sensitivity, embodied regulation, cultural responsiveness, doctrinal rigidity, fragmentation load, affect tolerance, relational holding, grounding capacity, symbolic readiness, balance, and clinical adequacy can be represented transparently in conceptual modeling.

## Repository purpose

This article argues that post-Jungian clinical analytical psychology became stronger by revising Jung’s original symbolic framework through relational, developmental, trauma-informed, embodied, feminist, cultural, and clinically pragmatic approaches.

The code examples extend that argument through:

- synthetic post-Jungian clinical adequacy simulation;
- symbolic-readiness and balance-index modeling;
- dynamic clinical-evolution network modeling;
- relational, developmental, trauma-informed, embodied, and critical revision nodes;
- reproducible tables and figures;
- multi-language computational scaffolding;
- documented responsible-use limits.

## Responsible-use statement

These materials are for synthetic-data research, methods demonstration, conceptual modeling, institutional learning, and reproducible workflows. They are not intended for diagnosis, therapy, psychological assessment, clinical decision-making, employment screening, workplace surveillance, individual performance management, or individual evaluation.

## Suggested workflow

1. Review `article-metadata.yml` for article context.
2. Run the R simulation in `r/simulate_post_jungian_clinical_evolution.R`.
3. Run the Python network workflow in `python/post_jungian_clinical_network.py`.
4. Use `sql/schema.sql` to inspect the synthetic clinical-dimension structure.
5. Treat all outputs as illustrative and synthetic, not empirical findings.
